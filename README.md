# Codex Collab Demo

这是一个团队协作演示仓库：用一个小型 Shell 问候程序，演示从企业微信群提出需求，到 Codex 桌面对话接单、隔离开发、提交检查结果，再由真人审核的完整流程。

可以先运行示例，再接入协作。示例程序和测试都在本仓库；机器人、MCP 服务及接入工具由独立的 [codex-collab 工具仓库](https://github.com/jack506255560/codex-collab) 提供。

## 快速上手

运行示例需要兼容 POSIX 的 Shell；克隆仓库还需要 Git。macOS、Linux 可在终端执行以下命令，无需安装应用依赖或配置机器人。

```sh
git clone https://github.com/jack506255560/codex-collab-demo.git
cd codex-collab-demo

# 默认问候
sh greet.sh
# 输出：hello, world

# 指定姓名
sh greet.sh Alice
# 输出：hello, Alice

# 运行测试
sh test.sh
# 输出：base checks passed
```

已经有本地仓库时，直接进入仓库根目录执行 `sh greet.sh` 和 `sh test.sh` 即可。`greet.sh` 使用第一个参数作为姓名，未传参数或参数为空时使用 `world`。

## 接入桌面对话协作

按协作工具当前版本的接入文档，配置企业微信群和机器人、团队成员身份与职责、项目 MCP，并将对应成员绑定到一个已有的 Codex 桌面对话。为这个对话启用定时心跳，执行模式使用 `desktop_poll`。

接入完成后，需要保持电脑、Codex 桌面应用、对话心跳和本机机器人适配器可用。MCP 提供接单接口，心跳负责唤醒对话并调用接口；仅安装 MCP 或绑定对话，还不能持续接收任务。

### 提出需求与执行

在已配置的群里，实际 `@` 对应机器人，说明要改什么、允许修改哪些文件，以及如何验收。例如：

```text
@你的机器人 优化 README.md 的中文说明，补充项目用途和运行示例。
只修改 README.md，示例应与现有程序一致，sh test.sh 要通过。
```

从需求到结果的流程如下：

1. 本机适配器校验群消息权限，记录需求并回复需求编号。
2. 绑定对话在后续心跳中读取需求，根据团队职责创建任务，回复任务编号和分工；信息不足时先在群里追问。
3. 当前阶段的 Agent 认领任务，在分配的独立工作树和任务分支中开发，并定期续租。
4. Agent 运行检查、检查差异并提交；MCP 再运行固定检查，验证提交并推送任务分支。
5. 机器人通知结果、提交引用和下一步。需要阶段审核时先等待指定真人；审核通过或配置允许直接交接时，再由下一位成员接力。
6. 所有阶段提交后，等待最终真人审核。任务完成与代码合并由后续人工操作处理。

群里回复“已收到”表示需求已进入队列，执行要等绑定对话的心跳认领。处理进度以同一个任务编号的通知和桌面对话中的执行记录为准。

### 真人审核与退回

审核通知会给出审核人、任务编号和审核版本（`R-` 后的数字）。由通知指定的真人在群里 `@` 自己对应的机器人，发送完整命令：

```text
@审核人自己的机器人 协作 审核 <任务ID> R-<版本号> 通过
@审核人自己的机器人 协作 审核 <任务ID> R-<版本号> 退回 | 具体修改意见
```

将 `<任务ID>` 替换为通知中的完整 `T-…` 编号，将 `R-<版本号>` 替换为最新审核通知中的完整版本号，并实际选择对应机器人的群内 `@`。两条命令选择一条发送；“协作 审核”前缀是命令的一部分，只发送任务编号和“退回”不会完成审核。

退回时说明具体修改点，例如“补充真人审核命令，并明确哪些配置需要另行安装”。正式退回后，原阶段会从已提交的版本继续修改，重新提交后使用新通知中的审核版本。

阶段审核通过后，任务按配置进入下一阶段。最终审核通过后，管理员可按通知发送完成命令：

```text
@管理员自己的机器人 协作 完成 <任务ID>
```

完成命令记录任务完成，代码分支仍需按项目约定通过 PR 或人工流程合并到 `main`。Agent 提交结果后等待真人审核，不自行批准或合并。

## 分支与交接约定

- `main` 保存示例代码、测试和说明文档。
- `agent-collab` 保存任务及协作事件记录，不应合并回 `main`。
- 代码和文档修改在任务分配的独立分支中进行；多阶段任务从上一步的准确提交接力。
- 交接应包含简明结果、检查证据以及准确的提交或 PR 引用。
- 密钥、个人配置、私有路径和完整聊天记录不应提交到仓库。

## 常见问题

**收到需求编号，为什么还没有开始修改？** 需求接收和任务执行是两个步骤。先确认对应的桌面对话心跳、项目 MCP 和机器人适配器可用，再查看是否正在等待补充信息、认领或真人审核。

**测试通过，为什么 `main` 没有更新？** 检查通过后提交的是任务分支。真人审核、任务完成和代码合并分别处理，推送任务分支不会自动修改 `main`。

**`--upper` 可以使用吗？** 当前程序只支持姓名参数，`test.sh` 也只覆盖默认问候和姓名问候。早期演示任务 `T-001` 中的 `--upper` 是待实现功能示例；有任务数据不等于已实现，也不等于已自动派发。

**应以哪个协议版本为准？** 本仓库的 `docs/agent-collab/` 是早期 v1 副本，`.codex/` 也是早期中心服务模式的配置说明，不会随个人工具安装自动升级。实际任务状态、租约、审核规则及接入方法，以当前安装的工具版本、MCP 返回结果和对应工具文档为准。
