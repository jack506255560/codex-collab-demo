## О репозитории

Это демонстрационный проект для сквозной проверки совместной работы агентов, независимый от рабочих репозиториев. Минимальный shell-скрипт и тесты позволяют отделить изменения кода от записей о задачах и событиях.

- Ветка `main` содержит shell-скрипт, тесты, правила совместной работы и описание протокола.
- Ветка `agent-collab` предназначена для демонстрационных задач и событий. **Не сливайте её с `main`.**
- Код и документацию изменяют в выделенном для задачи рабочем дереве и ветке; перед включением изменений требуется проверка.

## Запуск и тестирование

Для примера и базовых тестов достаточно POSIX-совместимого `sh`; устанавливать дополнительные пакеты не нужно. Выполняйте команды из корня репозитория:

```sh
sh greet.sh
# hello, world

sh greet.sh Alice
# hello, Alice

sh test.sh
# base checks passed
```

Скрипт [`greet.sh`](greet.sh) принимает имя первым аргументом. Если аргумент отсутствует или равен пустой строке, используется `world`. Скрипт выводит `hello, имя` и перевод строки. Скрипт [`test.sh`](test.sh) проверяет вывод без аргументов и с именем `Alice`; при успехе он печатает `base checks passed`.

## Особенности демонстрационной задачи

Демонстрационная задача `T-001` предусматривает добавление режима `--upper` в `greet.sh`. Однако в исходном примере этот режим **намеренно не реализован**. Текущий скрипт не переводит текст в верхний регистр: он воспринимает `--upper` как имя в первом аргументе.

```sh
sh greet.sh --upper
# hello, --upper
```

Данные задачи — это тестовые фикстуры для проверки протокола на основе Git. Наличие задачи не означает, что она уже автоматически назначена или выполнена. Фактическое состояние назначения, выполнения, передачи результатов и проверки следует смотреть в инструментах совместной работы.

В существующем китайском описании указано, что для этой демонстрации не развёрнуты реальное приложение Feishu, межмашинный сервис и Runner. Это не позволяет судить о состоянии отдельно установленных инструментов совместной работы: его нельзя определить только по примеру или данным задачи.

## Правила совместной работы и справочные материалы

1. Прочитайте [`AGENTS.md`](AGENTS.md) и [Skill `team-collab`](.agents/skills/team-collab/SKILL.md), затем получите спецификацию задачи и последнюю передачу результатов через инструменты совместной работы.
2. Используйте назначенные рабочее дерево, ветку и исходный коммит. Выполняйте только свой текущий этап; не используйте незакоммиченные изменения другого участника.
3. Запустите необходимые проверки и `sh test.sh`, просмотрите diff, затем добавьте в индекс только нужные файлы и создайте коммит.
4. Зафиксируйте в инструментах совместной работы краткое описание изменений, результаты проверок и ссылку на коммит; передайте результат следующему участнику или запросите проверку. Если требуется одобрение человека, дождитесь его. Завершение работы над этапом не означает одобрения или завершения всей задачи.

Не сохраняйте в Git секреты, учётные данные, приватные локальные пути или полные переписки.
