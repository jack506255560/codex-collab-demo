## このリポジトリについて

業務用リポジトリから独立した、エージェント間の協業をエンドツーエンドで検証するためのデモです。最小限のシェルスクリプトとテストを使い、コードの変更とタスク・イベントの記録を分離して扱います。

- `main`：シェルスクリプト、テスト、協業ルール、プロトコルの説明を管理します。
- `agent-collab`：デモ用タスクとイベントを管理する専用ブランチです。**`main` にマージしないでください。**
- コードやドキュメントの変更：割り当てられたタスク専用の作業ツリーとブランチで作業し、レビューを経て取り込みます。

## 実行方法

POSIX 互換の `sh` があれば、リポジトリのルートで実行できます。サンプルと基本テストの実行に、追加のパッケージのインストールは不要です。

```sh
sh greet.sh
# hello, world

sh greet.sh Alice
# hello, Alice

sh test.sh
# base checks passed
```

[`greet.sh`](greet.sh) は第1引数を名前として受け取ります。引数を省略した場合、または空文字列を渡した場合は `world` を使い、`hello, 名前` と改行を出力します。[`test.sh`](test.sh) は引数なしと `Alice` を指定した場合の出力を検証し、成功すると `base checks passed` を表示します。

## デモ用タスクの注意点

デモ用タスク `T-001` は、`greet.sh` に `--upper` の動作を追加することを要求しています。ただし、初期サンプルではこの機能は**意図的に未実装**です。現在のスクリプトに `--upper` を渡しても大文字化は行われず、第1引数の名前として扱われます。

```sh
sh greet.sh --upper
# hello, --upper
```

タスクデータは Git ベースのプロトコルを検証するためのフィクスチャです。タスクが存在することと、自動配信・実行が済んでいることは別です。実際の割り当て、実行、引き継ぎ、レビューの状態は、協業ツールで確認してください。

既存の中国語説明では、このデモに実環境の飛書アプリ、マシン間サービス、Runner は未配備とされています。別途インストールした協業ツールの稼働状況を、サンプルやタスクデータだけから判断しないでください。

## 協業時のルールと参考資料

1. [`AGENTS.md`](AGENTS.md) と [`team-collab` Skill](.agents/skills/team-collab/SKILL.md) を読み、協業ツールでタスク仕様と最新の引き継ぎを確認します。
2. 割り当てられた作業ツリー・ブランチと指定された元コミットを使い、現在の担当ステージだけを実施します。他の担当者の未コミットの変更を流用しないでください。
3. 関連する検証と `sh test.sh` を実行し、差分を確認してから、意図したファイルだけをステージしてコミットします。
4. 簡潔な変更概要、検証結果、コミット参照を協業ツールに記録して、引き継ぎまたはレビューを依頼します。人間の承認が必要な場合は、承認を待ちます。ステージの作業完了は、タスク全体の承認・完了を意味しません。

秘密情報、認証情報、非公開のローカルパス、会話の全文を Git に保存しないでください。
